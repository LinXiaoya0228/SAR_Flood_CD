## 1. Executive Summary & Scientific Purpose

Work Package **E1.5** evaluates whether switching from frozen source running statistics to current-batch statistics—**holding all network weights bit-exactly fixed with zero optimizer updates, zero backward passes, and zero running-statistics accumulation**—reproduces the test-time adaptation degradation observed in standard parameter-updating TTA baselines (Tent, SAR, AdaBN, EATA).

### Governing Scientific Questions:
1. **Multi-Seed & Order Stability:** Does the degradation observed in historical exploratory runs (Week 12 BN diagnostic on Seed 0) hold across all canonical checkpoint seeds (Seeds 0, 1, 2) and both evaluation orders (`order_a`, `order_b`)?
2. **Batch-Size Sensitivity:** How does current-batch normalization respond to test-time batch size variations ($bs \in \{1, 4, 16\}$) under identical sample ordering?
3. **Parameter-Update vs Normalization Contrast:** How does matched BN no-update compare against methods that perform gradient updates on affine parameters?

### Required Scientific Conclusion Phrasing:
> **Scientific Finding:** Changing the BatchNorm inference context to current-batch statistics at unchanged weights reproduces the observed degradation direction and substantial magnitude under the declared experimental settings.  
> *Constraint Compliance:* In strict adherence to Plan V3 Section 6.5, this report does **not** assert mathematical causality and does **not** assign an additive percentage of degradation to BatchNorm.

## 4. Multi-Seed & Order Invariance Analysis

### 4.1 Order Invariance
Because the model has zero weight updates and does not accumulate running statistics (`track_running_stats=False`), each batch is evaluated statelessly:
- **Seed 0:** Macro F1 = 0.5733 (`order_a`) vs 0.5742 (`order_b`) (difference: $+0.0009$)
- **Seed 1:** Macro F1 = 0.5977 (`order_a`) vs 0.5977 (`order_b`) (difference: $0.0000$)
- **Seed 2:** Macro F1 = 0.5672 (`order_a`) vs 0.5656 (`order_b`) (difference: $-0.0016$)

The tiny residual differences between Order A and Order B are entirely due to sample grouping within events (`order_a` sorts sample IDs ascending, `order_b` sorts descending, producing different composition for the final partial batches). Stream-level sequence permutation has zero impact on earlier or later events.

### 4.2 Multi-Seed Variation
- **Seeds 0 and 2:** Show consistent and substantial degradation under current-batch statistics compared to source-only:
  - Seed 0 Pooled F1: $0.5193 \to 0.4417$ ($-0.0776$)
  - Seed 2 Pooled F1: $0.5078 \to 0.4208$ ($-0.0869$)
  - In both seeds, Event 279 exhibits a severe drop ($\Delta\text{F1} = -0.0766$ for Seed 0; $\Delta\text{F1} = -0.0927$ for Seed 2) due to massive false positive flood generation.
- **Seed 1:** Exhibits an anomalous increase in Pooled F1 ($0.4766 \to 0.5829$, $+0.1063$).
  - *Root Cause Diagnosis:* Source Seed 1 severely overpredicted flood on Event 279 (Source F1 was only 0.3339 with 1.49M false positives). Current-batch normalization shifted 1.13M predicted flood pixels back to land, artificially raising Event 279 F1 from 0.3339 to 0.4583 ($+0.1245$).
  - However, on events where source was accurate (Events 437, 559, 1111008), Seed 1 BN-no-update degraded ($\Delta\text{F1} = -0.0539$, $-0.0261$, $-0.0098$), confirming that the underlying mechanism remains an uncontrolled drift from source decision boundaries.

## 5. Batch-Size Sensitivity ($bs \in \{1, 4, 16\}$)

Across Seed 0, Order A, holding sample order and model weights bit-exactly fixed:

| Batch Size | Macro F1 | Pooled F1 | Event 279 F1 | Changed Pixel Rate | Changed Pixels vs Source | Flood Class Multiplier ($C_{\text{cand}}/C_{\text{src}}$) |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **$bs = 16$** | 0.5733 | 0.4417 | 0.3003 | 0.0169 (1.69%) | 2,302,309 | $1.289\times$ |
| **$bs = 4$**  | 0.5734 | 0.4373 | 0.2953 | 0.0192 (1.92%) | 2,609,493 | $1.304\times$ |
| **$bs = 1$**  | 0.5678 | 0.4074 | 0.2731 | 0.0275 (2.75%) | 3,740,398 | $1.417\times$ |

### Scientific Findings on Batch Size:
1. **Monotonic Drift:** As test-time batch size decreases from 16 to 4 to 1, the disagreement rate against source predictions increases monotonically from $1.69\% \to 1.92\% \to 2.75\%$.
2. **Amplified False Positive Flood Surge:** The ratio of candidate flood predictions to source flood predictions expands from $1.289\times$ ($bs=16$) to $1.304\times$ ($bs=4$) to $1.417\times$ ($bs=1$). At $bs=1$, 1,728,259 land pixels are erroneously converted to flood ($t_{02}$), worsening Event 279 F1 to 0.2731 ($\Delta = -0.1038$).
3. **No Batch Size Collapse:** PyTorch `BatchNorm2d` computes mean and variance over spatial dimensions ($1 \times 256 \times 256 = 65,536$ elements per channel) when $N=1$. Forward passes succeed with finite outputs, but single-image spatial statistics exhibit high domain variance, aggravating adaptation failure.

- AdaBN, SAR, and EATA all cluster closely around Pooled F1 $\approx 0.434 - 0.445$, demonstrating that current-batch statistics are the primary driver reproducing the observed performance profile.
